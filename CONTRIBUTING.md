# Contributing

Thanks for wanting to help. This is the default guide for the public repositories of
[@ValentinTorassa](https://github.com/ValentinTorassa) that don't have their own. Where a repository
has its own `CONTRIBUTING.md`, as [Open Security Labs](https://github.com/ValentinTorassa/Open-Security-Labs)
does, follow that one.

## Before writing code

- For anything bigger than a small fix, open an issue first: what you want to change and why. If it
  doesn't fit the project, you find out before doing the work.
- Security problems never go in a public issue: see [SECURITY.md](SECURITY.md).

## Pull requests

- One change per pull request, small enough to review in one sitting.
- Run the repository's checks before opening it (each README says how) and keep CI green.
- In the description, say what changed, why, and how you checked it.
- Never commit secrets, real credentials or other people's data. When an example needs one, use an
  obviously fake value (`example.com`, `AKIAEXAMPLE...`, `user_42`).

## Style

- Follow what the repository already does: formatting, naming, and the language of its comments and
  docs. Some projects are written in Spanish and others in English.
- Commit messages say what changed and why.

## License

By contributing, you agree that your contribution is released under the license of the repository it
goes into.

## En español

Para algo más grande que un arreglo chico, abrí primero un issue y contá qué querés cambiar y por qué.
Un cambio por pull request, con los checks del repo en verde y una descripción de qué cambia y cómo lo
probaste. Nada de secretos ni datos de terceros: en los ejemplos, valores claramente falsos. Respetá el
estilo y el idioma de cada repo. Las vulnerabilidades se reportan en privado (ver
[SECURITY.md](SECURITY.md)).
