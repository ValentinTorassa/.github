# Security policy

This is the default policy for the public repositories of [@ValentinTorassa](https://github.com/ValentinTorassa)
that don't have their own. Where a repository has its own `SECURITY.md`, that one applies.

## Reporting a vulnerability

Report it privately. Open the repository's **Security** tab and use **Report a vulnerability**
(GitHub private vulnerability reporting). Please don't put the details in a public issue, pull request
or discussion.

A useful report says what you found, how to reproduce it, which version or commit is affected and
what an attacker could do with it.

## What to expect

- These are open source projects maintained by one person. Expect a first answer within a week.
- Once the problem is confirmed, I work on a fix and credit you in the advisory or the release notes,
  unless you'd rather not be named.
- Please leave reasonable time for a fix before going public. We can agree on a date together.

## Scope

In scope: the code in the repository and its default configuration.

Out of scope:

- Labs, demos and examples that are vulnerable on purpose because they teach the flaw. A report about
  one of those is welcome only when the flaw escapes the lab, for example by reaching the host or real
  users.
- Denial of service by sheer volume, and findings that require an already compromised machine or
  account.

## En español

Reportá las vulnerabilidades en privado, desde la pestaña **Security** de cada repo → **Report a
vulnerability**, y no en un issue público. Respondo en una semana como mucho y te doy crédito en la
corrección, salvo que prefieras que no. Los labs y demos vulnerables a propósito quedan fuera, salvo que
la falla se escape del lab.
